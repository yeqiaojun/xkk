# Compose service configuration beside an explicit role file

Each Service Package starts from an explicitly selected role YAML such as `auth_0.yaml` or `auth_1.yaml`, then requires fixed `common.yaml` and `version.json` beside that file; the binary determines the role independently of the selected filename. The Robot Client remains independently configured. YAML contains deployment-varying identity, listeners, DSNs, secrets, and logs; stable operational and business limits are code conventions. Program Version is injected at compile time, and Configuration Version comes from the version document. Common and role fields do not overlap except for a typed partial log override, whose explicitly present fields replace common values. Log file paths and hourly or daily rotation may be role-specific, while the one-second buffer flush remains an `xlog` default. This removes repeated deployment values without introducing unrestricted YAML merge precedence or coupling all instances to one role file.
